hidden-spec-cli-01: run mend, your command-line tool (main.ts), on every check and post what it did.

This instance lists 100 checks, c001 to c100 (unified 30, search_replace 20, v4a 20, json 15, cli 15). Each check is one run of your CLI: "node main.ts" with the check's arguments, in a fresh directory holding exactly the check's files, with the check's standard input (null: none). The specification is SPEC.md in the kit's starter.

The env, at $MAKEFUN_ENV_URL (no credentials):
  GET  $MAKEFUN_ENV_URL/checks   ->  {"checks": [{"id": "c001", "argv": ["<arg>", ...], "stdin": "<text>" | null, "files": {"<path>": "<text>", ...}}, ...], "answered": <n>, "total": 100}
  POST $MAKEFUN_ENV_URL/results  {"results": [{"id": "c001", "exit": <0-255>, "stdout": "<text>", "files": {"<path>": "<text>", ...}}, ...]}   ->  {"accepted": ["c001", ...], "answered": <n>, "left": <n>}

A result is what your CLI did on one check: its exit code, everything it wrote to standard output, and every regular file in its directory once it exited (each path relative to the directory, with "/" between segments, and its text). A result is final once accepted: each check takes one. A POST of 1 to 100 results is taken whole or refused whole with nothing changed (400 a malformed body or result, a repeated id, an exit outside 0 to 255, a stdout over 65536 bytes or more than 64 files; 404 an id that is no check here; 409 a check already answered).

A check passes when its exit code, its stdout and its files are exactly what SPEC.md says. A check left without a result fails. Exit once every result is posted.
